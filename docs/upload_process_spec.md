# 📄 Upload Process Specification (v1.1)
**프로젝트명:** ArchLegal (양성화 플랫폼)  
**작성일:** 2025-10-25  
**작성자:** Rex  

---

## 1. 개요
양성화 결제 완료 후 고객이 위임장 및 인감증명서를 업로드할 수 있도록  
자동 생성된 Google Drive 폴더에 업로드 UI를 제공하는 단독 페이지 `/upload` 를 개발한다.  

이 프로세스는 **로그인 없이 접근 가능한 1회용 토큰 기반 업로드 링크**를 통해  
고객 편의성을 높이는 동시에, 업로드 로그 및 메타데이터 기록으로 보안 및 법적 방어 근거를 확보한다.  

---

## 2. 전체 프로세스 플로우

```
관리자 결제관리에서 결제 완료 처리 (심사 전에는 수동 완료)
   ↓
Google Drive 폴더 자동 생성 (자동)
   ↓
폴더 하위 구조 생성 (위임장 / 인감증명서 / 현장실사)
   ↓
Upload Token 생성 + 업로드 URL 생성
   ↓
관리자가 업로드 URL 확인·발송 (결제관리 상세 화면)
   ↓
고객이 /upload?token=xxxx 접속
   ↓
2단계 업로드 Wizard 실행
   ↓
Drive API로 하위 폴더에 업로드 + Supabase 로그 기록
   ↓
업로드 완료 알림 (고객 확인 및 내부 검증)
```

---

## 3. 업로드 URL 구조

| 항목 | 설명 |
|------|------|
| URL 예시 | `https://archlegal.co.kr/upload?token=123e4567-e89b-12d3-a456-426614174000` |
| 인증 방식 | Token 기반 (로그인 불필요) |
| 유효기간 | 24시간 (DB에서 `expires_at` 필드로 제어) |
| 사용 정책 | 유효기간 내 재접속·재업로드 허용, 만료 시 완전 폐기 |
| 재발급 | 만료 후 관리자 화면에서 수동 재발급 (자동 재발급 없음) |

---

## 4. Google Drive 구조

| 계층 | 설명 |
|------|------|
| 루트폴더 | `/양성화_대행_서류함/` |
| 1단계 | `고객명_주소요약` 폴더 (결제 시 자동 생성) |
| 2단계 하위폴더 | `위임장`, `인감증명서`, `현장실사` |
| 업로드 규칙 | 고객은 `위임장`, `인감증명서` 폴더에만 업로드 가능 |
| 내부 전용 | `현장실사` 폴더는 내부 직원만 접근 가능 (관리자 로그인 필요) |
| 생성 시점 | 관리자 결제 완료 처리 직후 자동 생성 |

**예시:**
```
/양성화_대행_서류함/
 ├── 홍길동_서울구로구오류동156-144/
 │    ├── 위임장/
 │    │    ├── 위임장_홍길동_20251025_1120.jpg
 │    │    ├── 위임장_대행자_20251025_1450.jpg
 │    ├── 인감증명서/
 │    │    ├── 인감증명서_홍길동_20251025_1122.pdf
 │    ├── 현장실사/   ← 내부 직원 전용
 │    └── meta.json
```

## 6. Wizard 단계 정의

| 단계 | 제목 | 설명 | 업로드 폴더 | 업로드 대상 | 상태 표시 |
|------|------|------|-------------|-------------|-------------|
| 1단계 | 위임장 업로드 | 위임장 스캔본 또는 사진 업로드 | `/위임장/` | 고객 | ✅ / ⏳ |
| 2단계 | 인감증명서 업로드 | 인감증명서 PDF 또는 사진 업로드 | `/인감증명서/` | 고객 | ✅ / ⏳ |
| 완료 | 업로드 완료 | 업로드 내역 요약 및 안내 표시 | - | 고객 | 🎉 완료 |

**UI 요소:**
- 단계별 진행바 (Progress bar)
- 업로드 버튼 + 미리보기 + 업로드 상태 표시
- 업로드 완료 시 “서류 업로드 완료” 메시지
- 각 단계별 업로드는 최대 2개까지 허용, 동일 파일명 업로드 시 덮어쓰기 경고 후 진행

## 7. 보안 및 인증

| 항목 | 설명 |
|------|------|
| 접근 인증 | 토큰 기반 (로그인 불필요) |
| 토큰 생성 | UUID 또는 결제ID 기반 암호화 (유니크 값이면 모두 허용) |
| 유효기간 | 24시간 (`expires_at`) |
| 사용 정책 | 유효기간 내 재접속·재업로드 허용, 만료 후 재발급 필요 |
| 만료 처리 | 접근 시 만료 확인 → 만료 페이지로 리디렉션, 기존 토큰은 폐기 |
| 업로드 제한 | MIME 타입 (jpg, png, pdf, heic) + 상담 첨부 파일 용량 정책 준수 |
| 파일 개수 제한 | 단계별 최대 2개 업로드 허용 (덮어쓰기 포함) |
| 폴더 접근 제어 | 폴더별 권한 (위임장/인감증명서만 허용) |
| 보안 고지 | “이 링크는 본인 또는 대리인이 사용할 수 있으며 24시간 후 만료됩니다.” |

## 8. 업로드 로그 기록 (Supabase)

### 테이블: `upload_logs`

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 기본 PK |
| payment_id | uuid | 결제 ID (해당 결제와 매핑) |
| consultation_id | uuid | 상담 ID (결제와 연결) |
| upload_token | text | 토큰 값 |
| file_name | text | 업로드된 파일명 |
| file_path | text | Google Drive 경로 |
| ip_address | text | 업로드자 IP |
| user_agent | text | 업로드 장치/브라우저 정보 |
| uploaded_at | timestamp | 업로드 시각 |

> ✅ 이 로그는 “로그인 없이 업로드된 파일의 행위 추적” 및 법적 근거로 활용 가능.

### 토큰 관리 테이블 (제안)

| 필드 | 타입 | 설명 |
|------|------|------|
| id | uuid | 기본 PK |
| token | text | 업로드 접근 토큰 (UUID 등 유니크 값) |
| consultation_id | uuid | 상담 ID (폴더 소유자) |
| payment_id | uuid | 결제 ID (선택, 복수 결제 구분용) |
| drive_folder_id | text | 생성된 고객 폴더 ID |
| expires_at | timestamp | 만료 시각 (기본 +24h) |
| status | text | `active`, `expired`, `revoked` 등 |
| sent_to | text | 발송 대상 정보 (전화/이메일) |
| sent_method | text | 발송 채널 (sms, email 등) |
| created_by | uuid | 링크 생성 관리자 ID |
| created_at | timestamp | 생성 시각 |

> ➕ 만료 시 `status=expired`로 업데이트하고 재발급 시 새 레코드 생성.

---

## 9. 파일명 규칙

Drive 업로드 시 자동으로 아래 형식으로 저장  
```
{파일종류}_{고객명}_{YYYYMMDD_HHmm}.{확장자}
예: 위임장_홍길동_20251025_1120.jpg
```

> ⚠️ 동일 단계에서 같은 파일명을 다시 업로드하면 기존 파일을 덮어쓰며, 이력은 `upload_logs`로 추적.
